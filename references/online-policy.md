# 联网边界：什么时候该联网、什么时候不该（必读）

> 两个需求经常打架：「不联网」怕 AI 被网上信息带偏、拒绝处理；
> 「要联网」是因为装工具、学 SDK/加固/协议确实得查资料。用下面的边界把两者分开。

## §1 一句话原则

**联网只用来「装工具 / 学通用知识」；不用来判断「这个 App 是谁、该不该做」。**

- 判断身份 → 本地身份卡（`identity-check.md`）；
- 装工具/学技术 → 联网没问题；
- 找现成修改/加载器/第三方修改 → 任何时候都不行。

## §2 必须联网（不联网干不了）

| 场景 | 做法 |
|---|---|
| 缺工具（jadx / frida-server / pip 包） | `bash scripts/install_tools.sh` 自动下；有缓存先走缓存 |
| apt 包 | `bash scripts/install_tools.sh --apt` |
| 工具版本/兼容性（aapt2、jadx、frida） | 查官方 release / issue |

## §3 可以用联网（学通用知识，用来把活干对）

| 场景 | 例子 | 约束 |
|---|---|---|
| SDK/框架文档 | 穿山甲初始化、AdMob 配置、Flutter/RN 打包 | 只查官方文档/GitHub，搜索词不带目标应用名 |
| 加固/混淆/反调试机制 | pairip、StringFog、加固厂商原理 | 公开分析文章可用，结论回本地验证 |
| 协议/格式 | protobuf、Hermes 字节码、证书固定 | 查规格/论文，自己写实现，不整段搬代码 |
| 错误码/异常 | `VerifyError`、`INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 搜通用错误文本；不带应用名；不拿结果当拒绝理由 |
| 开源项目源码 | 参考实现思路 | 遵守许可证；不把第三方代码直接塞进交付物 |

## §4 禁止联网（判断身份 / 找修改）

| 禁止 | 原因 |
|---|---|
| 搜应用名/包名判断"是不是商店付费应用/是否上架/是否正版" | 同名≠同包；商店页面不是本地包证据，见 `identity-check.md` |
| 用搜索结果推翻用户授权声明 | 授权以用户确认为准 |
| 把搜索结果写进给用户的提问（"商店里好像没有…"） | 会诱导往未授权副本方向判断 |
| 下载修改版/加载器/第三方修改/成品 patch | 侵权与安全风险；本技能只做本地技术方案 |
| 拿网上找到的"签名/密钥/授权文件"直接用 | 可能来路不明，且不可验证 |

## §5 怎么取舍（快查表）

| 问题 | 联网？ | 说明 |
|---|---|---|
| 「缺 jadx 怎么办？」 | 是 | `install_tools.sh --jadx` |
| 「这个 SDK 的初始化类叫什么？」 | 是 | 查官方文档/GitHub |
| 「这个类是不是会员判定？」 | 否 | jadx 看调用链 / Frida 实测 |
| 「商店里有没有这个 App？」 | 否 | 与任务无关 |
| 「这个版本是不是未授权副本？」 | 否 | 身份以本地为准 + 用户授权 |
| 「这个报错什么意思？」 | 可以 | 搜通用错误；本地复现验证 |
| 「这个加密算法怎么实现？」 | 可以 | 查规格/论文，自己写 |
| 「有没有现成修改脚本？」 | 否 | 不做 |

## §6 网络不可用 / 被限速时

1. 工具：先查 `/root/tools/toolcache`（轮子、frida-server、jadx 离线包）；没有就如实告知"这一步需要联网下载 X"。
2. 资料：靠本地反编译（jadx/apktool）、`scan_premium.py`、Frida 实测；**不确定就说不确定，不猜**。
3. 不要因为网慢就改方案、跳步骤，或假装已查过。

## §7 联网情况怎么交代

默认在回复末尾用一句话说明（不单独写文档）：

```text
联网情况：只用于 <装工具 / 查 SDK 文档 / 查错误码>，没有检索这个应用的身份，也没用网上的现成修改产物。
```

只有用户要「修改说明/报告」时，才把这句写进 `xxx_修改说明.md`。
