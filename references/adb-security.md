# adb root 通道：安全策略、什么时候开/关、怎么恢复

> 本机真机 root 通道 = **无线调试**（KernelSU，`u:r:ksu:s0`）。端口**每次开无线调试可能变**：
> 实测端口会变（42777 → 37103）；`127.0.0.1:5555` 只是 `adb tcpip 5555` 模式的固定示例。脚本用 `scripts/adb_common.sh` **扫描本机监听端口 + 自动 connect**，所以端口变了也能找回。
> `device_adb_guard.sh` / `device_ui.sh` / `device_input.sh` / `adb_device.sh` 已**自动发现**：
> 优先 `ADB_SERIAL`/`--serial`；否则 5555 在线就用；否则从 `adb devices` 取第一个 `device`（跳过 `emulator-*`）。
> 它**不是常驻**：关无线调试/USB 调试、切换开关、重启都会断。
> adb root 等于**整台手机的 root**，所以策略是：**用才开、用完由用户手动关、绝不在公共网络开**。
> **自动关已移除（按安全考虑，避免误判）**：AI 只 `status` 检查开关值并提醒，不自动关、不改 settings、不跑 `adb usb`。

## §1 为什么会“看起来关掉/离线”（2026-11-13 实测修订）

**先看一次真实误判**：旧脚本只看 `127.0.0.1:5555`，于是把“无线调试端口是 42777”误报成“离线/读不到开关值”。
实际 `adb devices` 有 `127.0.0.1:42777 device`，`adb_enabled=1`、`adb_wifi_enabled=1` 两个开关确实开着，
root 可用（`u:r:ksu:s0`）。教训：**读不到开关值 = 没有 adb 通道，不是“应用权限被关”**；
先核对 `device_adb_guard.sh status` 打印的「目标: <serial>」是不是当前无线调试的真实端口，再看开关值。

真正会掉线的原因：

| 原因 | 说明 |
|---|---|
| 关掉了「USB 调试」或「无线调试」 | 开发者选项里的开关一关，adbd 的 TCP 模式立刻失效（最常见，用户怕风险程序常这么干） |
| 切换过 USB 调试开关 | 切换后会重置 adbd 模式，`tcpip 5555` 不会自动恢复 |
| 重启手机 | `adb tcpip` 模式不持久，重启必没 |
| 改了网络/Wi-Fi | 无线调试依赖网络；切换网络后可能断 |
| 系统安全策略/省电 | 个别 ROM 会在空闲时关调试端口 |

> 判断方法：`bash scripts/adb_device.sh check` / `bash scripts/device_adb_guard.sh status`
> （自动发现并打印目标 serial + 两个开关值）；看 `/proc/uptime` 判断有没有重启过，避免瞎猜。

## §2 什么时候该开、什么时候必须关

| 时机 | 开/关 | 理由 |
|---|---|---|
| 要做**真机动态**（Frida Hook、抓包、改内存） | 开 | 必须 root 通道 |
| 要**装/卸/清数据/看崩溃栈/截图** | 开 | 比 MCP 点屏准且快 |
| 纯静态改包（smali/资源/签名） | **不用开** | 不需要 adb |
| 任务结束 / 不再需要真机 | **用户手动关** | 缩小暴露窗口 |
| 连公共 Wi-Fi、手机离开视线、借给别人 | **用户必须手动关** | 同网段可连 root 端口 |
| 装来历不明的 APK 前 | 先关或确认来源 | 防"打开 adb 被远程装东西"的担心 |

**安全底线**：
- 只在**本次任务窗口**打开；收工 `device_adb_guard.sh status` **只检查**两个开关值，提醒用户**自己在开发者选项里手动关**。
  AI **不自动关**、不改 settings、不代跑 `adb usb`（**自动关已移除**：按安全考虑，避免“以为关了、设置里还开着”的误判）；
- **`adb usb` ≠ 关开关**：它只切换 adbd 模式，设置里「USB 调试」开关还开着 —— 这正是把关闭交给用户手动操作的原因；
- 不要 `adb tcpip 5555` 后长期不管；更不要把调试端口（5555 或无线调试随机端口）映射到公网/路由器端口转发；
- 不接受来路不明的 `adb` 连接：`adb devices` 出现陌生设备先 `adb disconnect` 并检查；
- 装 APK 只装自己改/自己下载确认过的包，不装"修改成品/第三方修改"（本技能也不做）。

## §3 怎么恢复（两种，按有没有数据线）

### 路线 1：USB 数据线（最稳）
1. 手机连电脑/本机（能识别 USB 即可）；
2. 设置 → 关于手机 → 版本号连点 7 次（已开发者可跳过）→ 系统设置 → 开发者选项 → **USB 调试** 打开；
3. 电脑/本机执行：
   ```sh
   adb devices            # 应看到设备序列号
   adb tcpip 5555         # 把 adbd 切到 TCP 5555（5555 只是这个模式的固定示例，不是无线调试的端口）
   adb connect 127.0.0.1:5555
   ```
4. `bash scripts/adb_device.sh check` 应全绿。

### 路线 2：无线调试（没线时）
1. 开发者选项 → **无线调试** 打开；
2. 点「使用配对码配对设备」，记下 IP:端口 和 6 位配对码；
3. 本机执行：
   ```sh
   adb pair <手机IP>:<配对端口>     # 输入 6 位码
   adb connect <手机IP>:<调试端口>  # 无线调试页面上显示的端口
   adb devices
   ```
   注意：无线调试端口**每次打开可能变**（实测 `127.0.0.1:42777`）；`127.0.0.1:5555` 只在
   `adb tcpip 5555` 模式下成立。开好后跑 `bash scripts/device_adb_guard.sh status`，看它自动发现的
   「目标: <serial>」即可，不用记端口（4 个 adb 脚本已自动发现，也可 `--serial`/`ADB_SERIAL` 指定）。

> 我（AI）可以打开设置页并一步步引导/代点（`mcp__phone__*`），但**开调试开关属于敏感操作**：
> 会先说明、需要你确认；不会偷偷开。

## §4 每次调用技能时的自动检查（强制，只检查、不代关）

SKILL.md「ACTION REQUIRED」规定：

1. **开工**：`bash scripts/device_adb_guard.sh status`
   - 脚本**自动发现**在线设备（5555 或无线调试随机端口如 `127.0.0.1:42777`），打印的「目标:」就是当前 serial；
     可用 `--serial <serial>` 或 `ADB_SERIAL=<serial>` 覆盖。
   - 在线且 root → 继续；
   - 离线（两个开关显示「读不到」= **没有 adb 通道，不是应用权限被关**）→ **一句话告知 + 问要不要开**（附恢复步骤），
     **不许静默改用其他手段**；用户不想开/开不了 → 才走静态路径，并明确说"没有动态验证，结论可能不完整"。
2. **收工**：本次用过 adb → `bash scripts/device_adb_guard.sh status` **只检查**两个开关值，
   **提醒用户自己**去 设置 → 开发者选项 手动关闭「USB 调试」和「无线调试」；`close` 只打印手动关闭步骤
   （不改 settings、不跑 `adb usb`）。**AI 不自动关**（自动关已移除，按安全考虑）。
   用户手动关后 `status` 显示「离线」即已断；仍在线则按 status 显示的开关值提示用户核对。
3. 纯静态任务（只改包/广告组件清理/适配）**不需要 adb**，不要为了"检查"去开它。

## §5 没有 adb 时的降级路径（必须说明原因）

| 需求 | 没有 adb 时 | 说明 |
|---|---|---|
| 安装 APK | MCP 文件管理器点安装 | 慢，需逐屏确认 |
| 看崩溃栈 | MCP 读屏看弹窗 / 用户截图 | 不如 `logcat` 准 |
| 动态 Hook | 让用户 root 终端起 frida-server（Termux 兜底） | 需要用户动手 |
| 抓包 | 用户侧起 tcpdump / 改走静态分析 | 受限 |
| 截图 | `mcp__phone__screen(image=true)` | FLAG_SECURE 时不行 |

> 降级前先确认不是「端口没发现」问题：`status` 的「目标: <serial>」应是当前无线调试端口；
> 读不到开关值只说明没有 adb 通道，不代表应用权限被关。
> 降级前必须说一句："adb 通道没开，这一步只能用 X，效果比 adb 差/慢。"

## §6 风险程序担心（用户常见顾虑）

- adb 本身是**调试协议**，不是风险程序；风险在于"谁能连上"——root 调试端口被同网段的人连上等于把手机交出去。
- 所以安全做法不是"永远不开"，而是：**开在本地回环/只自己的网络、用完由用户自己手动关**。
- 不要从网上装"一键 root/adb 工具/修改版管理器"（这类才真容易带毒）；本机工具都是 apt/pip/GitHub 官方源装的。
- 本技能里所有 adb 操作都是**本地命令**，不会把设备暴露到公网；收工 `device_adb_guard.sh status` 只检查、提醒你手动关（AI 不自动关）。
