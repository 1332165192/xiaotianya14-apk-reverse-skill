# 三种运行环境对比（本机 proot / Termux / 桌面 Agent）

> 结论先说：**Skill 本身只是“方法论 + 脚本”**，能力来自它调用的工具链（jadx/apktool/Frida/签名工具等）。
> 本技能的设计目标是：**不装 Termux、不依赖电脑**，直接在一台已 root/可授权的安卓手机上跑完整个流程。

| | 本技能（手机 proot） | Termux 方案 | 桌面 Agent 方案 |
|---|---|---|---|
| 运行位置 | 手机上的 Linux 容器（本 App 自带） | 手机上的 Termux 终端 | 电脑（Claude Code/Codex 等）|
| 需要电脑 | 不需要 | 不需要，但工具要自己装 | 需要 |
| 真机验证 | 内置（ADB/Shizuku/MCP 手机操控） | 需要自己接 ADB | 电脑连手机 |
| 设备操控/输入 | 内置脚本（device_ui / device_input） | 手写命令 | 电脑侧 adb |
| 大工具（Ghidra/IDA）| 不建议（内存小）→ 远程主机 | 不建议 | 适合 |
| 适合场景 | 解包/反编译/补丁/重打包/真机验证/发布 | 轻量命令行 | 深度 native 分析、批量任务 |

## 什么时候用哪种

1. **只有一台手机**：用本技能，全流程能走通；Ghidra/IDA 这类重工具不装，native 深挖时再借远程主机。
2. **手机 + 电脑都有**：手机做“解包/补丁/重打包/真机验证”，电脑做深度 native 分析，产物用文件/报告来回传。
3. **只用 Termux**：也能跑本技能的脚本，但要自己补齐工具（jadx/apktool/frida），并且没有本技能的设备操控与发布管线。

## 边界

- 本技能不替代 Ghidra/IDA 的静态反汇编能力；它负责“手机端能闭环的那一段”。
- 任何环境都遵守同一同意边界：仅自己拥有或已获授权的应用。
